# 虚拟内存与页面置换

<!-- page: 1 -->
## 为什么需要虚拟内存

虚拟内存为每个进程提供独立、连续的虚拟地址空间，再由页表映射到分散的物理页框。这样做的直接好处有三点：进程之间地址隔离，程序不需要关心物理内存布局，操作系统可以把暂时不用的页换出到磁盘。

虚拟地址通常被划分为页号和页内偏移。以 4 KiB 页为例，低 12 位是页内偏移，高位是虚拟页号。地址翻译由 MMU 查页表完成，页表项中除了物理页框号，还保存有效位、访问位、脏位和权限位。

<!-- page: 2 -->
## 页表与地址翻译

多级页表把巨大的页表拆成树状结构，只为实际使用的地址区间分配页表页。TLB 是页表项的硬件缓存，命中时不需要访问内存中的页表；未命中时才进行页表遍历。

地址翻译的基本顺序是：先查 TLB，未命中再查页表，页表项无效则触发缺页异常。缺页异常由操作系统处理，它需要判断这次访问是首次加载、页面被换出，还是越界访问。

<!-- page: 3 -->
## 缺页与页面置换

缺页中断发生时，如果还有空闲页框，操作系统直接把目标页读入内存。如果没有空闲页框，就必须选择一个牺牲页换出，再装入目标页，这个过程叫页面置换。

置换算法的目标是降低缺页率。理想算法是 OPT，它换出未来最长时间不会被访问的页，但需要预知未来，只能作为评价基准。实际系统常用 LRU、Clock 或改进型 Clock 算法。

<!-- page: 4 -->
## LRU 与 FIFO 的对比

FIFO 按页面进入内存的先后顺序淘汰，实现简单，但可能出现 Belady 异常：增加页框数反而让缺页次数上升。LRU 按最近使用时间淘汰，认为最近最少使用的页最不可能马上被访问，通常比 FIFO 更接近 OPT。

LRU 的难点是精确记录访问顺序，硬件开销较大。实际系统常用 Clock 算法近似 LRU：每个页有一个访问位，扫描时把访问位为 1 的页清零并跳过，遇到访问位为 0 的页就淘汰。LRU 不会出现 Belady 异常，FIFO 可能。

## 工作集与抖动

工作集是进程在一段时间窗口内实际访问的页面集合。如果分配给进程的页框数小于工作集大小，进程会频繁缺页，系统把大量时间花在换页上，这种现象叫抖动（thrashing）。

缓解抖动的方法包括：按工作集调整页框配额、降低多道程序度、使用页面错误率控制（PFF）动态分配页框，以及把换页 I/O 与计算重叠。
