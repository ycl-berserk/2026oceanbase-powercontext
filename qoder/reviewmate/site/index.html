THE PROBLEM

复习最耗时的，不是学，是找。

笔记散落在多门课、多个文件里；搜到一句话，却不知道来自哪一页； 上次标记的薄弱点，换一个工具就丢了。

01

想不起关键词

只记得“那个换页算法”，纯关键词检索却什么也搜不到。

02

答案没有出处

大模型答得流畅，却无法回到笔记原文核对，复习不敢信。

03

每次从头开始

薄弱点、进度、上次问过什么，散在聊天记录和脑子里。

THE LOOP

一次提问，串起检索与记忆。

问“LRU 和 FIFO 有什么区别”，答案回到操作系统笔记第 4 页； 标记薄弱点后，复习计划把它排到第一步。

  1. 问自然语言提问，可限定课程。
  2. 找seekdb 一条 SQL 融合全文与向量召回。
  3. 核每个引用带标题、章节、页码与原文。
  4. 记PowerContext 自动记录进度，薄弱点可手动标记。
  5. 复下一次提问与复习计划继续使用这些记忆。

UNDER THE HOOD

两种技术，各做一件不可替代的事。

SEEKDB

负责找到原文

  • 单表存储正文、元数据与 512 维向量
  • 一条 UNION ALL SQL 同时跑 NGRAM 全文与 HNSW 向量
  • 课程过滤在数据库层完成，再在 Python 侧做 RRF 融合
  • QA 日志记录问题、证据片段、回答模式与耗时

RUN IT YOURSELF

三步，从零到一次带记忆的问答。

需要 Linux / WSL、Python 3.11+。首次运行需联网下载中文 embedding 模型，之后可离线。

01

安装与启动记忆服务

python3 -m venv .venv
.venv/bin/python -m pip install -e ".[dev]"
cp .env.example .env

# 终端 A
make powercontext
02

导入笔记并启动界面

# 终端 B
make ingest
make serve

# 打开 http://127.0.0.1:8090
03

跑同一组验收

make verify
make test
make lint

没有大模型 Key 也能完整运行：默认使用本地摘录回答，引用与原文定位不受影响。 配置 DEEPSEEK_API_KEY 后自动切换为生成的回答。
