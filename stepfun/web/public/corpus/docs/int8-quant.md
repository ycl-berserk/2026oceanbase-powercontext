# INT8 量化

量化是把模型权重从高精度浮点压到低精度整数的过程。INT8 量化把每个 float32 权重映射成 8 位整数，配合一组缩放因子（scale，有时还有 zero point）在计算时还原近似值。理论压缩比是 4 倍，实际文件大小还要考虑量化参数与算子覆盖率。

主流做法是训练后动态量化（dynamic quantization）：不需要重新训练，只对权重做量化，激活值在推理时按动态范围量化。对 Transformer 的线性层效果稳定，体积能压到原来的四分之一，速度在 CPU 上有提升（整数运算更快、内存带宽压力更小）。

精度损失要实测。对嵌入模型，量化影响的不是"答得对不对"，而是向量的细微偏移，最终体现在检索指标上（Recall@K、nDCG@K）。经验上 INT8 对短文本嵌入的影响很小，Recall@5 通常只下降零点几个百分点到一两个百分点；但在语义边界模糊的查询上，排名可能发生交换。

一个常见误区是"压缩比越高越好"。4 位量化（q4）能把体积再砍一半，但嵌入质量下降明显，且部分后端不支持相应的算子，反而更慢。工程上建议把 FP32 作为基线、INT8 作为默认、FP16 作为 WebGPU 上的折中，三者都保留可切换，用同一份评测集对比后再定默认值。

在 Transformers.js 里，`dtype: 'q8'` 会加载 `model_quantized.onnx`（动态量化权重），`dtype: 'fp16'` 加载半精度权重，`fp32` 是原始权重。模型仓库里通常同时提供这几个文件，体积可以直接对比。
