# 索引刷新与增量写入

写入和"可检索"在向量库里是两件事。新数据落盘后，HNSW 这类图索引不会立刻包含它，需要一次索引刷新（refresh）才能被近似检索到。seekdb 提供 `CALL dbms_index_manager.refresh()`，seekdb-js 把它封装成 `collection.refresh_index()`。

刷新是相对重的操作，代价随集合规模增长。一个实测现象是：对 600 个 512 维分块，单次刷新约 0.6 秒；如果每写一批就刷新一次（6 批），累计约 4 秒，而"全部写完只刷一次"只要 0.6 秒，节省约 85%。所以批量导入的正确姿势是：多批写入时先不刷新，最后一次刷新。

但增量导入场景又不能完全不刷新，否则用户导入完立刻搜索会搜不到。折中策略是：一次导入流程结束时刷新一次；如果是持续的小批量写入，可以按时间窗口合并刷新（例如 2 秒内的写入合并成一次 refresh），并在界面上明确提示"索引刷新中"。

还有一个易踩的坑：刷新是全局的，刷新期间写入仍然可以继续，但刚写入的数据在刷新完成前不可见。因此写入接口最好返回"刷新耗时 + 写后自检结果"，让前端能明确告诉用户当前数据是否已经可检索，而不是让用户去猜。
