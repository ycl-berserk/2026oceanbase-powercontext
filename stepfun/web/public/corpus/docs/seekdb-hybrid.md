# seekdb 的混合检索

混合检索要解决的问题是：只靠向量会漏掉精确关键词，只靠全文又不懂同义改写。典型例子是查询"RRF 融合参数"，向量检索能把语义相近的段落找出来，但对"RRF"这种缩写不敏感；全文检索能精确命中缩写，却会漏掉用"倒数排名融合"表述的段落。

seekdb 通过 `DBMS_HYBRID_SEARCH` 提供数据库侧的混合检索。调用方把一个 JSON 形式的 `search_parm` 交给数据库，其中可以包含 `query`（全文匹配条件）、`knn`（向量近邻条件）和 `rank`（融合策略）。数据库根据这份参数生成执行计划，内部同时跑全文召回与向量召回，再按指定策略融合，最后返回 top-N 结果。

这一点对工程实现很重要：融合发生在数据库引擎里，而不是客户端先取两路结果再用代码拼起来。客户端只需要提交"查询文本 + 查询向量 + 融合参数"，召回与排序完全由 seekdb 负责，结果里同时带有 `_score`（融合分数）和原文、元数据。

在 seekdb-js 中对应的方法是 `collection.hybridSearch({ query, knn, rank, nResults })`。`query` 与 `knn` 都可以单独省略：只给 `query` 就是纯全文检索，只给 `knn` 就是纯向量检索，两者都给才是混合检索。
