# 检索评测指标

检索质量要量化，不能靠"看起来还行"。最常用的三个指标是 Recall@K、nDCG@K 和 MRR。

Recall@K 衡量"该找到的有没有找到"：在前 K 条结果里命中的相关文档数，除以相关文档总数。它不关心排序位置，只看覆盖。知识库场景里 Recall@5 是最直观的指标——用户只看前五条，漏掉就是漏掉。

nDCG@K 在覆盖率之外还考虑排序：每条结果按位置打折（`1 / log2(i+2)`），相关文档越靠前贡献越大，最后用理想排序归一化到 0 到 1。它适合对比"结果都在，但顺序对不对"。

MRR（Mean Reciprocal Rank）只看第一条相关结果的位置，取其排名的倒数再平均。它对"有没有很准的第一条"特别敏感，适合问答类场景，但对多相关文档的查询不敏感。

评测方法上要注意三点。第一，标注集要固定：同一批查询、同一套金标文档，才能比较不同模型与精度。第二，块级命中要映射到文档级再去重，否则同一篇文档的多个块会重复计分。第三，要报告样本量与聚合方式（均值还是中位数），并保留每次查询的明细，方便定位是"整体下降"还是"个别查询崩了"。

这三个指标对量化的敏感度不同：INT8 常见的现象是 Recall@5 基本不变，但 MRR 有小幅下降，因为相关文档还在前五里，只是顺序被微调。所以技术说明里最好三个指标都给。
