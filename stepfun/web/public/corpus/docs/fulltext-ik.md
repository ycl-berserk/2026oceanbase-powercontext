# 全文索引与中文分词

全文索引解决的是"精确匹配词语"的问题。英文天然有空格分隔，中文没有，所以必须先分词。seekdb 的全文索引支持指定分词器，中文场景常用 `ik`（IK Analyzer），并提供 `smart` 模式：把长词切成较粗的粒度，避免"中华人民共和国"被拆成单字导致召回噪音。

建索引时通过 `new FulltextIndexConfig('ik', { ik_mode: 'smart' })` 声明。之后就可以用 `MATCH ... AGAINST` 或 SDK 里的 `whereDocument: { $contains: '关键词' }` 做全文匹配。`$contains` 传入的字符串会被分词器处理，再按自然语言模式匹配。

分词器的选择直接影响召回：颗粒度太细会把无关文档也召回（噪声大），太粗则可能漏掉同义表达。实践中建议保持查询词与文档使用同一套分词配置，并在中文场景对专有名词（如产品名、缩写）做自定义词典补充。

一个常见误区是把整段自然语言问题直接丢给全文检索。全文检索擅长的是关键词命中，而不是理解意图；所以在混合检索里，全文那一路更适合传"精炼的关键词"，向量那一路传完整的问题。本项目的检索界面就允许单独填写关键词，默认沿用查询原文。
