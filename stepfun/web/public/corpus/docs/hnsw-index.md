# HNSW 向量索引

HNSW（Hierarchical Navigable Small World）是目前最常用的近似最近邻索引之一。它把向量组织成多层图结构：上层稀疏，用来快速"跳"到目标区域；下层稠密，用来做精细搜索。查询时从顶层入口点出发，逐层贪心地走向离查询向量更近的邻居，最后在底层做一次小范围搜索得到结果。

相比暴力扫描，HNSW 把查询复杂度从线性降到接近对数级，代价是额外的内存占用（每个向量要存若干条边）和构建时间。三个关键参数是：`M`（每个节点的邻居数，越大越准也越占内存）、`ef_construction`（建索引时的候选队列长度）、`ef_search`（查询时的候选队列长度）。调大 `ef_search` 通常能提升召回率，但延迟随之上升。

在 seekdb 里创建向量索引时通过 schema 指定，例如 `new VectorIndexConfig({ hnsw: { dimension: 512, distance: 'cosine' } })`。距离度量常用 `cosine`（文本嵌入一般已归一化）、`l2` 与 `inner_product`。索引维度必须和写入向量的维度严格一致，否则写入会被拒绝。

HNSW 是近似算法，因此"写入了但查不到"有时不是 bug，而是索引还没刷新，或者该向量在近似搜索的候选之外。前者需要刷新索引，后者需要调大 `ef_search` 或扩大候选窗口。
