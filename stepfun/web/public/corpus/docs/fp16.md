# FP16 与混合精度

FP16 用 16 位表示浮点数：1 位符号、5 位指数、10 位尾数。相比 FP32，它的表示范围更小、精度更低，但体积减半、内存带宽占用减半，在支持半精度运算的硬件上吞吐可翻倍。

在 GPU 上，FP16 通常比 INT8 更"安全"：不需要反量化，数值行为更接近原始模型，精度损失往往可以忽略。代价是压缩比只有 2 倍，而且并非所有设备都支持 FP16 运算——WebGPU 规范里 `shader-f16` 是可选特性，WASM 则根本没有 FP16 指令支持。因此 FP16 的适用场景主要是"支持 WebGPU 且适配器支持 f16"的环境。

混合精度训练/推理的思路是：权重存 FP16，累加与归一化等敏感操作用 FP32，兼顾速度与数值稳定。推理框架一般已经处理好了这些细节，使用者只需要选择 `dtype`。

实践中，端侧嵌入模型的三档配置可以这样定位：FP32 是准确率基线，也是体积基线；FP16 用于 WebGPU 加速且对精度敏感的场景；INT8 用于体积与加载时间优先的场景（例如首次访问、移动网络）。三者维度相同，可以共用同一套数据库表结构，只是向量数值略有差异，所以对比评测必须各自建集合、各自向量化，不能混用。
