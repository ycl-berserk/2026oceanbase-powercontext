# 浏览器模型缓存与首次加载

端侧应用的用户体验很大程度上由"第一次打开"决定。模型文件动辄几十兆，如果每次都重新下载，用户会直接关掉页面。浏览器的 Cache Storage 是标准解法：把模型文件按 URL 缓存成响应对象，第二次加载直接命中本地。

Transformers.js 默认使用名为 `transformers-cache` 的缓存空间，缓存的是模型权重、分词器配置等文件。开发时可以通过 `env.useBrowserCache` 与 `env.cacheDir` 调整策略。缓存条目保留了原始响应头，因此可以遍历缓存、按 URL 过滤出某个模型的文件，把 `content-length` 累加，得到"该模型实际占用的字节数"——这是做体积对比最可靠的方式，比读文档里的数字更贴近真实。

首次加载的计时必须单独统计。它包含三部分：文件下载、ONNX 图加载与优化、首帧推理（含 WebGPU 管线编译）。三者加起来的"冷启动"时间往往是后续单次推理的几十倍。合理的界面设计是：下载阶段显示进度条与当前文件，初始化阶段显示"正在初始化推理后端"，就绪后再允许用户操作。

缓存也有坑。同一模型的不同精度（fp32/fp16/int8）是不同文件，会分别占空间；切换精度意味着重新下载。做多档对比评测时要注意磁盘占用，并提供清理入口。另外浏览器可能在存储压力下清理缓存，所以"已缓存"不能当作永久保证，降级路径依然要能用。
